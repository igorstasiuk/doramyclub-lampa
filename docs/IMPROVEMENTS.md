# Doramy.club → Lampa: исследование сайта и план улучшений плагина

Дата исследования: 2026-11-03. Сайт смотрели встроенным браузером Claude (отдельная вкладка) только на чтение: `get_page_text`, `read_page` и `fetch` с того же origin. Формы не отправлялись, оценки, списки и комментарии не менялись.

**Метки достоверности**
- **[OK]** — проверено: страница или ответ получены и разобраны.
- **[КОД]** — прочитано в JS сайта (`js.js`, `sea.js`, `rand.js`, `navi-list.js`, `gidreg.js`, `comm.js`, `fav_scripts.js`, `aktfav_scripts.js`, `postratings-js.js`), но сам запрос не выполнялся (у него есть побочный эффект).
- **ПРЕДПОЛОЖЕНИЕ** — вывод, который без входа или изменения данных подтвердить нельзя.

> Важная оговорка о сессии. Во встроенном браузере уже была **активная сессия аккаунта пользователя** (её открыли не в ходе этого исследования, логин не выполнялся). Поэтому страницы `/regs-*` и профиль отдавались как для авторизованного пользователя. Их читали только ради структуры разметки. Личные данные (логин, e-mail, IP, содержимое списков) в документ **не внесены**. Гостевой вид `/regs-*` увидеть не удалось: запрос без cookie (`credentials:'omit'`) получает anti-bot-заглушку, а не страницу. Всё, что ниже сказано про гостя на этих страницах, — ПРЕДПОЛОЖЕНИЕ.

Состояние плагина сверялось по `README.md`, `CHANGELOG.md` и `doramyclub.js`. Пока шло исследование, в рабочей копии появилась версия **0.2.0** с синком аккаунта по вставленному cookie (`ACCOUNT_LISTS`, очередь операций). Матрица ниже учитывает 0.2.0.

### 3.5 Плеер

**F20. Пропуск заставок (P2, M).**
- В Lampa есть сегменты: `Player.play({…, segments: {skip: [{start, end}], ad: []}})` — модуль `segments` ловит `data.segments` на `start`. Бандл ищет «заставку» в первых 45 % длительности со `start >= 30`.
- Kodik для дорам `skipButton` не даёт (`parseSkipButton("", "serial")`). Поэтому:
  - (а) если в странице серии Kodik `parseSkipButton("<данные>")` не пуст — разобрать и передать (формат — ПРЕДПОЛОЖЕНИЕ, проверить на аниме-тайтле);
  - (б) ручные метки «Начало/конец заставки» долгим OK в плеере — сохранять на тайтл и озвучку (`doramy_skip: {id+voice: {start,end}}`) и применять ко всем сериям.
- Риски: у разных озвучек разный тайминг.

## 4. Авторизация и синхронизация с аккаунтом сайта

### 4.1 Как устроен вход

- Страницы входа, регистрации и восстановления — `/login`, `/regs-login`, `/regs-reg`, `/regs-lostpass`: у авторизованного пользователя они делают 302 на `/regs-vash-profil` **[OK]**. Форму входа увидеть нельзя без выхода из аккаунта — ПРЕДПОЛОЖЕНИЕ: Theme My Login, `POST /login` с полями `log`, `pwd`, `rememberme`, `instance`, `action=login`, редирект и `Set-Cookie: wordpress_logged_in_<hash>` (HttpOnly) + `wordpress_sec_<hash>`.
- `wp-login.php` закрыт отдельной серверной заглушкой (`?pass=1`) **[OK]**, вход идёт только через страницы темы.
- Выход: `/logout?_wpnonce=<nonce>` **[OK]**.
- Капча и 2FA не видны (ПРЕДПОЛОЖЕНИЕ). Anti-bot стоит перед всем сайтом, значит, перед формой входа тоже.

### 4.2 Списки и действия

- Чтение: `GET /regs-favorit|budu|view|zakl|broh` (+ `?strana=`) → `ul.fav-list li a[href]` (ID из `data-post` у `span.del-link*` или из URL), `img`, `b` **[OK]**. «Смотрю» = `/regs-view`, «Просмотрено» = `/regs-zakl` — названия путей контринтуитивные, их легко перепутать.
- Состояние одного тайтла дешевле читать со страницы тайтла: `a.<list>-link[data-action]` — `del` значит «уже в списке» **[OK]**. Это даёт сверку без загрузки всех `/regs-*`.
- Запись — таблица в 1.6 **[КОД]**. Нюанс для плагина 0.2.0: там удаление сделано как `wfm_del` и `budu_delh` / `viewed_delh` / `zakl_delh` / `broh_delh` («списочные» варианты). Со страницы тайтла сайт шлёт `*_del` — это **другие** серверные обработчики с другим HTML-ответом. Оба варианта должны удалять, но это ПРЕДПОЛОЖЕНИЕ, пока не проверено на аккаунте. Успех определять **повторным чтением состояния** (`data-action` на странице тайтла или наличие в `/regs-*`), а не по тексту ответа.
- Ответы — HTML-фрагменты, не JSON. Ошибки: при неверном nonce WordPress `check_ajax_referer` отдаёт `-1` или 403; без сессии — `0` или 400 (ПРЕДПОЛОЖЕНИЕ, стандартное поведение admin-ajax). Плагин должен считать `-1`, `0`, пустой ответ и HTML anti-bot-заглушки ошибкой и не снимать операцию из очереди.
- Защита: nonce (`wfmFavorites.nonce`, общий для страниц, живёт 12–24 ч) + cookie сессии. Брать nonce со свежей страницы тайтла или `/regs-*` с той же cookie; при `-1` — один раз перечитать nonce и повторить.
- «Мои актёры»: отдельный nonce `akterFavorites.nonce`, `termId` — ID терма актёра (`data-post` у `.akter-link`).

### 4.3 Что реально сделать из плагина на ТВ

| Вопрос | Ответ |
|---|---|
| Нативные запросы | На Android `Lampa.Reguest().native` → `Android.httpReq` → `AndroidJS.httpReq(JSON)`. Ответ — только тело (`AndroidJS.getResp`), **заголовки ответа, включая `Set-Cookie`, в JS не приходят** **[КОД бандла]**. Заголовки запроса (`Cookie`, `User-Agent`, `Referer`) передать можно (плагин уже так делает). Хранит ли Java-сторона cookie между запросами (CookieJar) — ПРЕДПОЛОЖЕНИЕ, скорее нет. |
| Вход по паролю из плагина | Нельзя надёжно: `Set-Cookie` недоступен, anti-bot стоит перед формой. Это совпадает с выводом в CHANGELOG 0.2.0. |
| CORS | В браузерной Lampa (webOS/Tizen/ПК) прямые запросы к сайту блокируются CORS; cookie другого домена через `$.ajax` не отправить (`withCredentials` + отсутствие CORS на сайте). Работает только Android-native или свой прокси. |
| Anti-bot-cookie | Сессионная cookie из браузера обычно вставляется вместе с `__js_p_`/`__jhash_`/`__hash_`/`__lhash_`/`__jua_`. `__jua_` — это UA браузера; плагин шлёт свой `DESKTOP_UA`. ПРЕДПОЛОЖЕНИЕ: при несовпадении UA anti-bot снова отдаст заглушку. Сайт сознательно защищён от автоматизированных клиентов, и подделка отпечатков ради прохода проверки — это обход защиты, его делать **не нужно**. Плагин должен только честно диагностировать причину (F24). Решение о допустимости — за владельцем плагина после проверки условий сайта. |
| Прокси | Свой прокси пользователя может держать сессию, но тогда cookie аккаунта лежит на прокси — это вопрос доверия, описать в README. |
| Альтернатива: QR-перенос | `Lampa.Utils.qrcode(text, el)` есть в бандле. Можно показать QR со ссылкой на инструкцию «как скопировать cookie». Перенос самой cookie через сторонний сервис — нет (утечка сессии). |

### 4.4 Схема синхронизации (рекомендации к 0.2.x)

1. **Модель.** Локальный список — операции `{id, list, op: add|del, ts, tries}` в очереди (`doramy_sync_queue`) + снимок сайта `doramy_remote: {list: {id: ts_seen}}` + локальные метки `doramy_marks`.
2. **Pull.** Читать 5 страниц `/regs-*` не чаще раза в час и вручную. Diff со снимком: исчезло на сайте → удалить локально (если нет более свежей локальной операции `add`); появилось → добавить.
3. **Push.** Очередь по одной операции, пауза 1–2 с, ретраи с backoff (1, 5, 30 мин), максимум около 5 попыток, затем пометка «не отправлено» в UI.
4. **Конфликты.** «Последняя запись по времени» на уровне пары (id, list). Локальная операция новее последнего pull — побеждает локальная; иначе сайт. Первая синхронизация — объединение (union), без удалений.
5. **Взаимоисключение статусов.** На сайте «На потом», «Смотрю», «Просмотрено», «Брошено» независимы: можно оказаться сразу в нескольких (ПРЕДПОЛОЖЕНИЕ, сервер не проверяли). Плагину не стоит навязывать эксклюзивность на сайте. Можно предложить опцию «переносить»: при `zakl_add` спросить «убрать из „Смотрю“?».
6. **Авто-статус «Смотрю»** (есть в 0.2.0): ставить только после N минут просмотра и не чаще одного раза на тайтл, чтобы не засорять список случайными запусками.
7. **Прогресс серий** на сайт не синхронизируется: сервер его не хранит, отметки `gidreg.js` лежат только в `localStorage` браузера. Прогресс остаётся в `Lampa.Timeline`/CUB.
8. **Офлайн.** Операции копятся в очереди. После ошибки сессии (заглушка, `0`/`-1` после повторного nonce) синк ставится на паузу с баннером «Сессия истекла — обновите cookie», очередь не теряется.

### 4.5 Безопасность хранения

- Пароль не принимать и не хранить (в 0.2.0 так и сделано). Хранить только cookie сессии в `Lampa.Storage`. Это `localStorage`, он не шифруется: показать предупреждение «кто имеет доступ к устройству, получит доступ к аккаунту». Кнопка «Отключить аккаунт» стирает cookie, nonce и очередь.
- Отправлять cookie только на `base()` сайта и никогда — на Kodik, прокси-префикс (если прокси не принадлежит пользователю — спросить) или зеркала другого домена без подтверждения.
- Не логировать cookie, nonce, e-mail, IP (в HTML Kodik есть `user_ip`). В «Диагностике» показывать маску: `wordpress_logged_in_…=*** (есть)`.
- Не сохранять e-mail из `/regs-vash-profil`; логин — только для отображения «Вы вошли как …», и лучше по запросу.
- Не синхронизировать `Lampa.Storage` с cookie через CUB: если Lampa синхронизирует настройки в облако, ключ `doramy_cookie` нужно исключить. ПРЕДПОЛОЖЕНИЕ: Lampa синхронизирует лишь часть ключей, проверить по бандлу (`Storage.sync`/список полей в `Account`).

### 4.6 Юридические и ToS-риски

- Сайт против автоматизированных клиентов (anti-bot, `noindex` на заглушке, `robots.txt` закрывает `/navi-cl`, `*/regs-`, `/wp-comments-post.php`). Чтение каталога по запросу пользователя — обычный клиентский сценарий, но массовые обходы (F8, F9) нужно ограничивать частотой и объёмом.
- Запись в аккаунт (списки, оценки, комментарии) от имени пользователя через неофициальный клиент может нарушать условия сайта. Пользовательского соглашения на сайте не нашли, есть `/kontakty` и `/pravoobladatelyam`. До выхода публичной версии с записью стоит написать администрации (контакт на `/kontakty`) и получить согласие.
- Видео — Kodik. Плагин берёт прямой поток в обход их iframe и рекламы (`adsbygoogle.js`, `forceAdvertCount`). Это риск по условиям Kodik и сайта, в README он уже косвенно отражён.
- Фишинговые клоны: сайт сам предупреждает о них. Не публиковать в плагине «рекомендованные зеркала» без проверки владельцем.
